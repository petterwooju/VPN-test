Use the Mac that owns the VPN profiles. Use Computer Use for online UI inspection and shell commands for measurements and state checks. The workflow uses macOS's own VPN client. The Apple Shortcuts VPN profile picker crashed on the original Mac, and `scutil --nc` could not enumerate those profiles, so drive the existing profiles through System Settings.

On this Mac Codex depends on FlClash for Internet access. Never ask the user to turn it off before preparation, or disable it in an isolated tool call and expect another model turn to connect Puma or restore connectivity. When local UI scripting is authorized, use the [offline pilot](references/offline-pilot.md): prepare and validate the complete local sequence while online, then let one process turn off FlClash, connect Puma, measure, disconnect and restore FlClash. Its independent watchdog must be armed before changes. Keep FlClash on when preparation or permissions fail. Skill instructions alone do not authorize a new UI automation mechanism or new Accessibility access.

1. Read [Mac workflow and recovery](references/macos-workflow.md). Before changing anything, create the run log and recovery note and capture the active physical service's DNS, route, VPN status, relay and FlClash state. Treat existing network sessions as user state. Authorized temporary suspension of FlClash belongs inside the prepared offline sequence; preserve its original TUN and proxy values. When testing an engine restart from a running baseline, use the offline pilot's `--cycle-fl-engine` option. Use only the dedicated `CoreaVPN_TEST` profile on this Mac. If another IKEv2 tunnel owns the test route, stop preparation and leave that connection as found.
2. For the offline-pilot.py single-method Puma and batch diagnostics, pass `--test-profile CoreaVPN_TEST`. The runner locates the profile by exact display name and saves its server address and remote ID before the temporary edit. Restore both fields after the test. Do not extract, echo, or log credentials. Any required administrator password goes directly into the Mac's Terminal.
3. For .net use the existing verified local relay or the compatible bundled copy. Confirm a public Puma DNS answer before connecting Puma. In engine restart mode, arm recovery before stopping FlClash, wait for the physical uplink, then start the relay against that uplink's DNS settings. The offline runner verifies the connected profile and the route to the selected measurement target. Use `--measurement https` (default) for [Cloudflare throughput and HTTPS latency](scripts/https_speed.py), or `--measurement icmp` for [20 pings to 168.126.63.1](scripts/vpn-ping.py). Use batch mode for a one-round check of multiple servers.
4. In the Mac app, start quick searches with Leo when the account supports it. The ping button retains the first tunnel with at least 18/20 ICMP replies and mean RTT at or below 100 ms. The FAST button independently requires at least 10 Mbps of verified Cloudflare download throughput. Upload failures and high idle latency do not disqualify a valid download. Use the original measurement precision for both decisions.
5. For a full Mac comparison use **전체 테스트 후 서버 선택** or [the local guardian](scripts/quick-search.py) with `--operation all` and omit `--hosts`. Every full run attempts the 23 servers in [the catalog](assets/servers.json), including all four group D and both group E servers, regardless of the saved account groups. Use the official hostname for both endpoint and remote ID on .com and .kr. Measure ICMP then HTTPS on each established tunnel, save partial results, and report any failure under the host and stage observed. After the last test, verify the original profile and uplink, FlClash engine, TUN, system proxy stability for 30 seconds and actual HTTPS. Leave the choice to the user. `--operation select` takes just the clicked server and verifies its fresh tunnel. Stop and release through the same local guardian.
6. Record the actual interface, ICMP replies/sent and RTT, HTTPS target, throughput and idle/loaded latency, failures and final recovery. Preserve method, run, attempt and physical network identity when importing history. See [server calibration and ranking](references/macos-workflow.md#server-calibration-and-ranking).
